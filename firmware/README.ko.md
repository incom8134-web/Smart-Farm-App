# 수업용 펌웨어

[English](README.md) | **한국어**

두 프로그램으로 감독하에 진행하는 수동 스마트팜 수업을 운영합니다. **아두이노 나노**는 센서를 읽고
블루투스 명령에 따라 세 가지 출력을 켜고 끕니다. **ESP32-CAM**은 Wi-Fi 공유기를 통해 사진과 실시간 영상을 제공합니다.
두 프로그램 모두 자동 급수나 식물 상태 판별은 하지 않습니다.

아두이노 IDE에서 `nano-controller/nano-controller.ino`와 `esp32-cam/esp32-cam.ino`를 엽니다.
ESP32 스케치는 폴더 전체를 함께 두세요. `.cpp`와 `.h` 파일도 프로그램의 일부입니다. 보드마다 프로그램은 하나입니다.

카메라는 수업 자료의 공유기 방식을 사용합니다. 휴대폰과 카메라가 같은 공유기에 접속하고,
앱에는 카메라가 시작할 때 출력하는 IP 주소를 입력합니다.

## 나노가 하드웨어 Serial을 쓰지 않는 이유

이 PCB에서는 나노의 하드웨어 UART가 ESP32 업로드 선과 연결되어 있어서, 나노가 시리얼로 출력하면
ESP32 업로드가 실패할 수 있습니다. 그래서 나노 프로그램은 하드웨어 `Serial`을 시작하지 않고,
HC-06 블루투스 모듈은 D8/D9의 `SoftwareSerial`을 사용합니다.

ESP32는 정상적으로 부팅할 때마다 115200 baud로 `Camera IP: <주소>` 한 줄만 출력하고, `Serial.end()`로
UART를 놓아 줍니다. **Core Debug Level: None**을 선택하세요. 다른 디버그 레벨이면 컴파일되지 않습니다.
프로그램 시작 전에 ESP32 ROM이 부팅 메시지를 낼 수 있으므로, 나노를 업로드할 때는 PCB 스위치로 두 보드를 분리해야 합니다.

## 업로드 절차

1. 모듈을 옮기거나 DIP 스위치를 바꾸기 전에 USB와 외부 전원을 분리합니다.
   첫 업로드와 출력 시험 때는 부하(조명, 팬, 펌프)를 연결하지 마세요.
2. 나노에 계속 출력하는 예전 스케치가 있다면, ESP32를 뺀 상태에서 이 폴더의 **최종 나노 스케치**를 먼저 업로드합니다.
   별도의 빈 스케치는 필요 없습니다.
3. 전원을 끕니다. ESP32를 다시 꽂고 DIP 스위치로 ESP32 프로그래밍 경로를 선택합니다
   (**1/3/5 ON, 2/4/6 OFF**로 알려져 있음 – PCB 설명서로 확인). 보드의 다운로드/리셋 순서를 따릅니다.
4. 아래 설정으로 ESP32를 **먼저** 업로드하고, 일반 부팅 모드로 되돌립니다.
5. 리셋하기 **전에** 시리얼 모니터를 115200으로 열어 한 번만 나오는 `Camera IP: <주소>`를 확인합니다.
   IP를 적어 두고 시리얼 모니터를 닫습니다.
6. PCB를 통한 ESP32 두 번째 업로드도 되는지 확인합니다.
7. 전원을 끕니다. 나노 프로그래밍 경로(**2/4/6 ON, 1/3/5 OFF**로 알려져 있음)를 선택하고
   최종 나노 스케치를 **두 번째로** 업로드합니다.
8. 전원을 끄고 일반 동작 모드를 선택합니다. 두 보드를 함께 쓰려고 DIP 스위치를 모두 ON으로 하지 마세요.
   어떤 경로를 동시에 켤 수 있는지는 PCB 문서에서만 확인할 수 있습니다.
9. 전원을 켜고 HC-06을 페어링한 뒤 출력을 하나씩 시험합니다.

일반 업로드만으로 이전 프로그램이 교체됩니다. 플래시를 지운다고 시리얼 충돌이 해결되지는 않습니다.
지우기 명령도 먼저 ESP32 부트로더와 통신해야 하기 때문입니다. ESP32를 완전히 지우려면
**Erase All Flash Before Sketch Upload: Enabled**로 한 번 업로드한 뒤 다시 **Disabled**로 돌려놓으세요.
나노의 **Burn Bootloader**를 지우기 용도로 쓰지 마세요.

## 아두이노 IDE 설정

| 항목 | 나노 | ESP32-CAM |
|---|---|---|
| 보드 패키지 | Arduino AVR Boards 1.8.8 | esp32 by Espressif Systems 3.3.2 |
| 보드 | Arduino Nano | AI Thinker ESP32-CAM |
| 프로세서 | ATmega328P (해당 나노에 필요할 때만 Old Bootloader) | AI Thinker 기본값 |
| 업로드 속도 | 보드 기본값 | PCB에서 빠른 속도가 불안정하면 115200 |
| 디버그 레벨 | – (하드웨어 Serial 사용 안 함) | Core Debug Level: None |
| PSRAM | – | 선택 가능하면 Enabled |
| 플래시 | 기본값 | 4 MB AI Thinker 모듈 |
| 파티션 | 기본값 | 포함된 `partitions.csv` (앱 하나, OTA 없음) |

라이브러리: **DHT sensor library 1.4.7**, **Adafruit Unified Sensor 1.1.15**, **LiquidCrystal I2C 1.1.2**.
같은 이름의 다른 LCD 라이브러리는 함수가 다를 수 있으니 이 버전을 사용하세요. Wire와 SoftwareSerial은
AVR 패키지에, 카메라·Wi-Fi·HTTP 라이브러리는 ESP32 패키지에 포함되어 있습니다.

## 나노 배선

| 신호 | 나노 핀 | 의미 |
|---|---|---|
| 생장등 드라이버 | D4 | 출력, `LED_ON` / `LED_OFF` |
| DHT11 | D5 | 온도(°C), 상대 습도(%) |
| 팬 드라이버 | D6 | 출력, `FAN_ON` / `FAN_OFF` |
| 펌프 드라이버 | D7 | 출력, `PUMP_ON` / `PUMP_OFF` |
| HC-06 TX | D8 | 나노가 9600 baud로 수신 |
| HC-06 RX | D9 | 나노가 송신 (모듈 쪽 PCB 레벨 변환 확인) |
| 조도 센서 | A0 | ADC 원시값 0–1023 |
| 수위 센서 | A1 | ADC 원시값 0–1023 (보정된 토양 수분값 아님) |
| LCD SDA / SCL | A4 / A5 | 16x2 LCD, 주소 0x27 (0x3F로 바꾸기 전에 스캔) |

부하를 분리한 상태에서 각 출력 핀의 ON/OFF 전압을 GND 기준으로 측정하고, 신호를 드라이버 단까지 따라가 확인합니다.
모터를 GPIO 핀에 직접 연결하지 마세요.

`LED_ACTIVE_HIGH`, `FAN_ACTIVE_HIGH`, `PUMP_ACTIVE_HIGH`는 각각 따로 설정하며 기본값은 모두 `true`입니다.
액티브 로우로 확인된 드라이버일 때만 `false`로 바꾸세요.

나노 프로그램은 세 단계로 배웁니다:

1. `readBluetooth()`가 기다리지 않고 명령 문자를 모읍니다.
2. 2초마다 `loop()`가 DHT11을 읽고 ADC 값 8개를 평균 냅니다.
3. `sendSensorPacket()`이 값을 보내고, `updateLcd()`가 LCD 화면 세 개를 번갈아 보여 줍니다.

DHT11은 측정 사이에 최소 2초가 필요합니다. 측정에 실패하면 LCD에는 `ERR`, 블루투스로는 오류 값이 나갑니다.
예전 값을 새 값처럼 보여 주지 않습니다.

저수위 차단이나 펌프 타이머는 없습니다. `PUMP_ON`은 `PUMP_OFF`, 리셋, 전원 차단 전까지 계속 켜져 있으며
휴대폰 연결이 끊겨도 마찬가지입니다. 반드시 감독하에 사용하세요.

## 블루투스 통신 규약

명령 여섯 개 중 하나를 보냅니다: `LED_ON`, `LED_OFF`, `FAN_ON`, `FAN_OFF`, `PUMP_ON`, `PUMP_OFF`.
소문자도 됩니다. 앱은 끝에 `;`를 붙이며, 끝 문자가 없어도 명령이 완성되면 바로 실행됩니다.
CR이나 LF도 끝 문자로 쓸 수 있습니다.

수신 버퍼는 16바이트입니다. 너무 길거나 잘못된 문자열은 다음 끝 문자나 500 ms 멈춤까지 버려지고,
완성되지 않은 명령도 그 멈춤 후에 사라집니다.

나노는 2초마다 값 네 개와 세미콜론을 보냅니다:

```text
24.5,60.0,410,330;
```

순서: 온도 °C, 습도 %, 조도 원시값, 수위 원시값. DHT 측정에 실패하면 온도 `-99.0`, 습도 `-1.0`을 보냅니다.
명령 확인 응답은 없습니다. 앱은 이 데이터로 부하의 실제 상태를 알 수 없으므로, ON/OFF 표시는 마지막으로 보낸 명령을 뜻합니다.

SoftwareSerial은 반이중 방식이고 DHT를 읽을 때 잠깐 인터럽트가 막힐 수 있어, 명령을 빠르게 연달아 보내면 일부가 사라질 수 있습니다.
명령은 하나씩 보내고 LCD나 출력을 확인하세요.

## 카메라

`esp32-cam.ino` 맨 위의 `WIFI_SSID`와 `WIFI_PASSWORD`를 설정합니다. 휴대폰과 카메라는 같은 2.4 GHz 네트워크에 있어야 합니다.
기기 간 통신을 막는 게스트 네트워크에서는 접속이 안 될 수 있습니다. 부팅할 때 출력된 IP를 사용하세요
(`192.168.4.1`은 이 프로그램의 주소가 아닙니다).

카메라는 시작 후 20초 안에 접속하여 웹 서버를 시작하거나, 오류 메시지를 한 번 출력하고 리셋을 기다립니다.
접속 후에는 Wi-Fi가 자동으로 다시 연결되지만 공유기가 새 IP를 줄 수 있으니, IP를 다시 보려면 카메라를 리셋하세요.

| URL | 결과 |
|---|---|
| `http://<ip>/` | 실시간 보기 시작/정지, 사진 링크 |
| `http://<ip>/capture` | JPEG 사진 |
| `http://<ip>:81/stream` | 앱이나 브라우저용 MJPEG 실시간 스트림 |
| `http://<ip>/status` | 카메라 형식 JSON |

가벼운 실시간 보기를 위해 320x240 JPEG로 고정되어 있습니다. 실시간 보기는 한 명만 지원하므로 새 스트림을 열기 전에
이전 스트림을 닫으세요. PSRAM이 없는 보드에서는 사진과 스트리밍을 동시에 하지 마세요.
머신러닝용 고해상도 데이터셋은 별도 수업이 필요합니다.

HTTP에는 비밀번호나 암호화가 없습니다. 신뢰할 수 있는 교실 네트워크에서만 사용하고 인터넷에 노출하지 마세요.
지정된 전원을 사용하고(무작위 리셋은 대개 전원 문제), 카메라 리본 케이블을 전원이 켜진 상태에서 꽂거나 빼지 말고,
ESP32 GPIO에 5 V를 넣지 마세요.

## 수업 전 교사 점검표

| 점검 | 기대 결과 |
|---|---|
| 부하를 분리하고 나노 전원 켜기/리셋 | 세 출력 모두 꺼진 상태 |
| 명령 여섯 개를 하나씩 | ON과 OFF마다 출력 핀과 LCD가 바뀜 |
| DHT11 정상, 이후 DHT11 분리 | 새 값, 이후 ERR / 오류 값 |
| 조도 센서 가리기/열기, 수위 센서 젖음/마름 | 원시값이 바뀜 |
| 길고 잘못된 블루투스 문자열 후 올바른 명령 | 잘못된 문자열은 무시, 다음 명령은 동작 |
| 부팅 후 나노 | 하드웨어 UART 출력 없음 |
| ESP32 시작 | IP 또는 오류 메시지 한 번 |
| 공유기 비밀번호 틀림 | 약 20초 후 시간 초과, 리셋 대기 |
| 사진 촬영, 스트림 정지/시작 여러 번 | 정상 이미지, 멈춤 없음 |
| PCB로 ESP32 두 번, 나노 두 번 업로드 | 정해진 스위치 순서로 매번 성공 |
| 전기 점검 후 부하 연결 | 조명, 팬, 펌프가 ON/OFF를 따름 |

## 개발자 검사

2026-10-19에 위의 패키지와 라이브러리 버전으로 컴파일했습니다:

| 프로그램 | 컴파일 | 플래시 | 정적 RAM |
|---|---|---|---|
| 나노 컨트롤러 (ATmega328P Old Bootloader) | 통과 | 10,208 / 30,720 바이트 | 670 / 2,048 바이트 |
| ESP32-CAM 카메라 | 통과 | 1,023,163 / 3,145,728 바이트 | 55,356 / 327,680 바이트 |
| 펌프 실습 | 통과 | 930 / 30,720 바이트 | 9 / 2,048 바이트 |
| 토양(A1) 실습 | 통과 | 3,570 / 30,720 바이트 | 283 / 2,048 바이트 |

보드 없이도 아두이노 IDE에 포함된 Arduino CLI로 컴파일할 수 있습니다. 저장소 최상위 폴더에서 실행합니다:

```text
arduino-cli compile --fqbn arduino:avr:nano:cpu=atmega328old firmware/nano-controller
arduino-cli compile --fqbn esp32:esp32:esp32cam firmware/esp32-cam
uv run --with ziglang==0.15.1 python firmware/check_firmware.py
```

`check_firmware.py`는 실제 나노 스케치와 HTTP 코드를 가상 장치와 함께 컴파일하여, 나뉘거나 합쳐진 명령, 잘못된 입력,
버퍼 넘침, 시간 초과, 센서 오류, 액티브 로우 출력, 타이머 넘김, 카메라 버퍼 정리를 시험합니다.
전기적 타이밍, DHT 신호, 실제 Wi-Fi 기기는 시뮬레이션하지 않습니다.

`sensor-tests/`의 스케치는 부품 하나씩 배우는 실습입니다. 토양 실습은 A1을 읽고, 펌프 실습은 꺼진 상태에서 시작해
감독하에 3초 ON / 3초 OFF를 반복합니다.
